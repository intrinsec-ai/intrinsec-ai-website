Why a baseline

The list of things that go wrong keeps growing.

Some failures are attacks. Some are just a deep stack breaking. From the outside they look the same: traffic that passes every check, behavior that isn't what you deployed.

One baseline surfaces
Prompt injection Jailbreaks Sensitive-data exposure Rogue tool calls Broken tool calls Hallucination Drift and off-domain use

The list isn't the product; the baseline is. Anything that doesn't match how your workload normally computes surfaces, including the failure modes no one has named yet.

Not just attacks

Tool calls that quietly fail.

Sometimes a tool call just breaks: a malformed argument, a schema that drifted, a result the model answers around. Nobody attacked you and nothing threw an error, but the model still computes differently, so it surfaces the same way an injection does.

How it works

Baseline. Surface. Tag.

Baseline

Learn how your model fires.

We watch the model behind your agent during normal traffic and build a baseline of normal for your workload, learned from your own traffic rather than a generic attack list.

Surface

Score every request against it.

Anything atypical stands out, whatever the source or modality, even when the input itself reads perfectly fine.

Tag

Label what surfaced.

DLP tagged data. We tag computation: domain, task, disposition, safety flags. Anomalies reach your alerting stack already labeled.

Where this goes

DLP tagged data. We tag computation.

A prompt is a control input: what matters is not what was said to the model, but how the model fires in response. We label that firing pattern on every KV page (domain, task, disposition, safety flags), off the request path. And because computation lives in one unified representation space, the labels are not bound to text or to any one modality.
